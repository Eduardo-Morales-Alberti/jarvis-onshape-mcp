# `sketches.json` contract (schema `sketchgen/1`)

This file is the hand-off to the FeatureScript skill. Keep it stable: add
fields, never rename or repurpose them. Bump the schema version for breaking
changes.

```jsonc
{
  "schema": "sketchgen/1",
  "part": "speedcad-t3-2",           // kebab-case, same as the designs/<part>/ folder
  "units": "mm",                     // all lengths mm, all angles degrees
  "origin": {                        // what sits at (0, 0) and why (the drawing's datum)
    "feature": "center of boss C",
    "evidence": ["vertex of the 60 deg angle", "start of the vertical 60", "..."]
  },
  "parameters": { "side": 60, ... }, // the design's single dimension table (name -> number)
  "material": { "name": "Steel", "density": 7850 },  // optional, kg/m3
  "target_mass_g": 891.754,          // optional: mass printed on the drawing
  "notes": ["..."],                  // heights, build order, open hypotheses
  "reference": { "image": "reference.jpg" },
  "sketches": [ Sketch, ... ],
  "build": ["S2_footprint/footprint", "S3_arms/arm_AB", "...", "S1_bosses/bore_A"]
}
```

`build` is the CAD feature order, one `"<sketch id>/<region id>"` per
extrusion or revolve. A step can also be a circular pattern group:
`{"circular_pattern": {"steps": ["S2_arm/arm", "S3_eye/boss_eye"], "axis": "Z", "count": 5, "angle": 360}}`.
Its steps build the seed bodies (the first one must be `NEW`; every body the group's steps
create is patterned, so use `NEW` for pieces that touch the main body but not each other);
the seed is copied `count - 1` times about the world axis (X, Y or Z through the
origin), evenly over `angle` (360 = full turn), and then everything is united. It is the only source of order for the converter: every region
with an `extrude_hint` appears exactly once, the first step is `NEW`, and
REMOVE steps come after the material they cut. `run.py` enforces all of it.

## Sketch

```jsonc
{
  "id": "S2_footprint",              // S<n>_<purpose>, unique
  "name": "S2_footprint",
  "plane": "Top",                    // Top | Front | Right (Onshape default planes)
  "offset": -11.66,                  // optional: plane moved along its normal (mm)
  "notes": "...",
  "entities":    [ Entity, ... ],
  "constraints": [ Constraint, ... ],
  "regions":     [ Region, ... ]
}
```

Each sketch is **self-contained**: shared construction geometry (for example
the skeleton triangle) is repeated in every sketch that needs it, so the
converter never has to resolve references across sketches.

Sketch coordinates are the plane's 2D frame, as Onshape uses it:
Top = (X, Y), Front = (X, Z), Right = (Y, Z) seen from +X.

## Entity

| type | fields |
|---|---|
| `point` | `at: [x, y]` |
| `line` | `start: [x, y]`, `end: [x, y]` |
| `circle` | `center: [x, y]`, `radius` |
| `arc` | `center`, `radius`, `start`, `mid`, `end`, `direction: "ccw"` |

All entities carry `id` (unique within the sketch) and `construction` (bool).
Arcs always run counter-clockwise from `start` to `end`; `mid` lies on the
arc, so both the Onshape `skArc(start, mid, end)` form and the center/radius
form can be built without recomputing anything.

## Constraint

```jsonc
{ "type": "TANGENT", "refs": ["f_A", "f_RAB"], "value": 45, "note": "callout 7" }
```

`param` (optional) names the entry of `parameters` the value comes from; it
is emitted automatically when `design.py` builds `P = Params({...})` and passes
`value=P["name"]`. Values computed from several parameters carry no `param`
and are literal. The FeatureScript side turns each `param` into a feature input.

`refs` name an entity (`"f_A"`) or one of its points (`"f_A.start"`,
`"f_A.end"`, `"f_A.center"`). `value` is only present on dimensional
constraints. See `constraints.md` for the full catalog, the refs each type
takes, and how the checker verifies it.

## Region

```jsonc
{
  "id": "arm_AB",
  "loop": ["a_RAB", "a_AB_B", "a_inAB", "a_AB_A"],   // closed chain, non-construction
  "holes": [["A_bore"]],                              // optional inner loops
  "extrude_hint": { "op": "ADD", "end": "BLIND", "height": 20 },   // or, for a section:
  // "revolve_hint": { "op": "NEW", "axis": "axis", "angle": 360 }
  "inside_point": [-29.75, 17.25],                   // generated: pick the face with qContainsPoint
  "note": "..."
}
```

- `loop` entities form a closed chain in order (each curve may be traversed in
  either direction). A single `circle` is a valid loop.
- `revolve_hint` (instead of `extrude_hint`): revolve the region about `axis`, a line
  entity of the same sketch (usually construction). The region must not cross the
  axis (`run.py` checks it). Only `angle: 360` is supported by the converter so far.
- `extrude_hint.height_param` (optional) names the parameter behind `height`.
- `inside_point` is generated by `sketchgen`: a point inside the region (outside
  its holes) at least 0.2 mm from every edge. The FeatureScript side selects
  the region's face with `qContainsPoint(qSketchRegion(sketchId), point)`.
  `run.py` also rejects any region crossed by another non-construction curve of
  the same sketch, since Onshape would split it into several faces.
- `extrude_hint` is a **hint** for the FeatureScript skill: `op` is one of
  NEW, ADD, REMOVE, INTERSECT; `end` is one of BLIND, THROUGH_ALL, SYMMETRIC,
  UP_TO_NEXT; `height` is required unless `end` is THROUGH_ALL. BLIND
  extrusions start on the sketch plane and go along its normal; SYMMETRIC ones
  are centered on the sketch plane (`height` = full thickness). When a part is
  symmetric in Z the sketch plane is its mid plane (see `notes`).
- Build order is `build` (top level), never the sketch order.
